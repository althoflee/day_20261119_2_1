# 예제 2 · 이전 대화를 기억하는 로컬 AI 채팅

이 예제는 Streamlit에서 질문을 받고, 로컬 Ollama의 `qwen3.5:2b`가 생성한 답변을 실시간으로 보여 준다. 앞선 메시지에 담긴 사실을 다음 질문에 활용하고, 모델이 같은 생각을 되풀이할 때는 그때까지의 추론을 사용해 답변을 마무리한다.

## 실행하기

Ollama를 실행한 뒤 프로젝트 루트에서 다음 명령을 실행한다. `ollama pull`은 모델을 처음 내려받을 때만 필요하다.

```powershell
ollama pull qwen3.5:2b
uv run streamlit run src/ex02/app.py
```

## 딸기 세 개로 대화 기억 확인하기

**대화 지우기**를 누른 뒤, 아래 문장을 같은 채팅에 **한 줄씩 따로** 입력한다.

| 차례 | 사용자 입력 | 확인할 점 |
| --- | --- | --- |
| 1 | 딸기가 3개 있습니다. | 처음 수량은 3개다. |
| 2 | 저와 친구가 1개씩 먹었습니다. | 두 사람이 각각 1개씩, 총 2개를 먹었다. |
| 3 | 몇 개 남았나요? | 앞선 두 메시지를 합쳐 `3 − (2 × 1) = 1개`라고 답하는지 확인한다. |

마지막 질문 한 문장에는 시작 수량도, 먹은 수량도 없다. [app.py](./app.py)는 매번 시스템 지시 뒤에 `st.session_state.messages`의 사용자 메시지와 완료된 답변을 시간순으로 붙여 모델에 보낸다. 수량은 모델이 대화를 읽고 계산한다. 처음 수량을 7개로, 각각 먹은 양을 2개로 바꿔 새 대화에서 실행하면 기대 답은 3개다.

## 추론이 반복될 때의 처리

Qwen3.5-2B는 추론을 반복하다가 답변을 쓰기 전에 생성 한도에 도달할 수 있다. 실제 딸기 예제의 실패 로그에서도 추론은 12,233자였고 답변 본문은 0자였다. 모델 개발팀도 스트리밍 중 반복을 감지해 중단하는 방법을 권한다. [Qwen3.5-2B 모델 카드](https://huggingface.co/Qwen/Qwen3.5-2B#thinking-mode)

1. [공유 모듈의 stream_text 함수](../shared/__init__.py)는 `reasoning=True`로 요청한다. 추론은 `reasoning_content`에서 모으고, 화면에는 `part.text`로 받은 답변 본문을 보낸다.
2. 답변이 시작되기 전, 추론이 **2,048자**에 도달하거나 **20자 이상인 같은 문장이 세 번** 나오면 스트림을 닫는다. 반복 횟수는 문장부호나 줄바꿈으로 끝난 구절의 대소문자와 공백을 정리한 뒤 센다. 이미 답변이 시작됐다면 본문을 계속 표시한다.
3. 첫 요청에서 본문이 오면 그 답변으로 끝낸다. 본문 없이 끝났을 때만 같은 대화로 한 번 더 요청한다. 두 요청은 한 질문의 추론 글자 수 한도를 공유한다.

### 답변을 쓸 때 추론을 잠시 끄나요?

**답변을 쓸 때도 `reasoning=True`다.** 보통은 모델이 한 요청 안에서 스스로 추론을 마치고 답변을 쓴다. 앱은 답변이 시작되는 순간에 별도의 요청을 보내거나 설정을 바꾸지 않는다.

반복이나 글자 수 한도로 추론 도중에 멈췄다면, 앱은 지금까지 받은 추론을 임시 assistant 메시지에 담아 두 번째 요청을 보낸다. 이때 `content="\n"`을 함께 보내면 Ollama의 Qwen3.5 렌더러가 기존 추론 뒤에 종료 표시(`</think>`)를 붙이고, 파서는 이어지는 출력을 답변 본문으로 읽는다. 따라서 모델은 같은 질문을 처음부터 다시 풀지 않고 이미 생각한 내용에 이어 답을 쓴다. 다음 질문의 대화 기록에는 완성된 답변만 남는다. [Ollama 0.40.14 렌더러](https://github.com/ollama/ollama/blob/v0.40.14/model/renderers/qwen35.go#L270-L288) · [파서](https://github.com/ollama/ollama/blob/v0.40.14/model/parsers/qwen35.go#L60-L78)

사이드바의 **최대 추론 글자 수**에서 256~8,192자를 선택할 수 있다. 작은 값은 빨리 답변으로 넘어가고, 큰 값은 여러 단계가 필요한 질문에 생각할 여유를 준다. 이 설정의 단위는 **글자**이며 최종 답변 길이에는 적용되지 않는다.

## 터미널 로그 읽기

한 질문에서 나온 로그는 `[shared/요청ID]`가 같다. 같은 ID에서 **질문 → 추론 원문 → 답변 원문**을 따라가면 모델이 어느 단계까지 진행했는지 볼 수 있다.

| 로그의 `done_reason` | 의미 |
| --- | --- |
| `reasoning_char_limit` | 앱이 설정한 추론 글자 수에 도달했다. |
| `repeated_reasoning` | 앱이 같은 추론 문장의 세 번째 등장을 감지했다. |
| `length` | Ollama가 길이 한도에서 생성을 끝냈다. |
| `stop` | Ollama가 생성을 정상 종료했다. 실제 답변은 **답변 원문**에서 확인한다. |

첫 시도의 **답변 원문 (0자)** 뒤에 같은 ID의 이어 쓰기 로그가 있으면, 두 번째 시도의 답변을 확인한다. 두 시도 모두 본문이 비면 앱은 오류를 표시한다. 조각별 추론·본문·메타데이터까지 보려면 PowerShell에서 `$env:OLLAMA_LOG_LEVEL = "DEBUG"`를 설정한 뒤 앱을 다시 실행한다.

대화 기록 전달, 반복 감지, 글자 수 한도, 빈 답변 처리는 프로젝트 루트에서 모델 서버 없이 검증할 수 있다. [회귀 테스트](../../tests/test_stream_text.py)

```powershell
uv run python -m unittest discover -s tests -v
```
